# clean_v3：可追溯的数据清洗候选版

本版由 `scripts/build_clean_v3.py` 从冻结的 v9 原始数据生成。它是独立候选数据集，尚未替换正式 clean_v2，也没有训练新模型、生成测试预测或重新评估测试成绩。原始数据、clean_v2、M1/M2 权重及 release 文件在构建前后逐文件校验，保持不变。

## 清洗结果

- 比赛仍为 **11,387 场**：train 7,260、val 1,968、test 2,159。与 clean_v2 对齐后，比赛 ID、时间、胜负标签和时间分区一致。
- 地图仍为 **12,387 行**。不为了让数据看起来完整而补造缺失地图。
- 选手统计表有 **118,323 条可用于 ADR/KAST 历史计算的地图—选手记录**，同时保留已通过检查的 K/D/A、ADR、KAST、KD 差字段。缺失 ADR/KAST 或没有有效选手 ID 的记录不在这张表中。
- **19 条地图记录**存在选手统计内部矛盾，排除整条地图的选手统计，保留比赛及地图比分，并标记需要复查。当前触发点是死亡次数超过该地图记录的总回合数；仅靠原始文件无法确定究竟是比分还是选手统计有误。
- **3 条低终场比分地图**单独标记复查。没有自动把它们判为错误、弃赛或 BO1，也没有修改比分。
- 通过同一比赛的重复汇总记录，补回 **1 个已在另一条记录中明确出现的缺失选手 ID**。不使用其他日期或相似队伍推测阵容。
- **114 条原始行**进入留档，包括缺失/不适用的比赛记录、重复汇总记录、缺失地图名的记录、冲突地图候选及其依赖记录。该数量包含 clean_v2 已经排除的记录，不能解读为新增删除了 114 场比赛。

机器可读的精确计数及 SHA256 清单见 `manifest.json`。`audit_entries` 按操作/单元格计数，`source_rows` 按原始行去重，`matches` 按比赛去重；同一原始行可能触发多个原因，不能把原因计数直接相加当作删除量。

## 具体规则与原因

### 队伍身份

队名执行 Unicode NFKC、空格规范化、大小写折叠，生成 `team1_key/team2_key`。原始显示名称和 ID 的对应关系保存在 `team_identity_audit.csv`。

原始文件中有 **22,788 个 team ID、982 个规范化队名**，其中 **861 个队名对应多个 ID**，因此原始 ID 不适合作为跨比赛的全局队伍主键。沿用以规范化队名维护历史的方式，不擅自合并改名、学院队、女队或名称相似的队伍。相同规范化名称是否存在不同时期的不同组织，仍需要外部证据核验。

### 比赛与重复记录

检查日期、队名、比分、tier 和重复汇总记录的身份/结果一致性。胜负只由系列赛比分产生，不使用不可靠的 `team1_win`。互相矛盾的重复汇总记录整场隔离，不任取一条作为真值。

重复阵容只要选手集合相同就不算冲突。已观察到的完整阵容可补全同场重复记录的缺失值；阵容互相矛盾时隔离该侧阵容。赛事中英文别名仅记录待核验，不声称已确认是同一个赛事。

### 地图

地图必须有接受的比赛主记录、非空名称、非负整数比分和可确认的队伍方向。地图日期与比赛主记录矛盾时隔离，不把错误时间直接覆盖。赛事名称等辅助元数据对齐主记录时记录前后值。

同场同图出现冲突比分时隔离全部候选；同比分重复地图如果选手统计冲突，保留地图结果但禁用无法确认的统计。不把异常的地图完成度标记作为赛前输入。

### 阵容与选手统计

选手 ID 必须是正整数；不将小数 ID 截断。队内重复 ID 隔离整侧阵容，跨队重复 ID 隔离双方阵容。保留此前的比赛级阵容隔离证据，避免预处理后原有错误标记丢失。

K/D/A 检查非负整数，ADR 检查非负有限值，KAST 检查 0–100，KD 差检查整数并与 K−D 核对。缺失保持缺失；不按分位数截断高 ADR，不把缺失值填成平均水平或假阵容。

### 防止结果泄漏

`bo_reported` 仅用于赛后质量核查；建模用 `bo` 仍全量未知，禁止从终场比分推断赛前赛制。

训练、验证特征按日期从历史重建，同一天先计算所有输入，再更新当日历史。不生成测试期特征或预测。`match_quality.csv` 的质量标记属于赛后审计数据，不进入 41 列 `design()` 输入。

## 文件怎么用

- `matches.csv`：一行一场，含清洗后的阵容和规范化队名。
- `maps.csv`：一行一张地图，含统计隔离和低比分待核验标记。
- `player_stats.csv`：通过筛选的地图级选手统计。
- `match_quality.csv`：比赛级质量标记。
- `audit_log.csv`：逐项原因、动作、原值、新值及来源位置。`source_row` 是原始 CSV 的数据记录序号加 2；若字段含嵌入换行，它不等于文本编辑器的物理行号。
- `quarantined_rows.csv`：隔离或去重的原始行，内容不被清洗值替换。
- `team_identity_audit.csv`：原始队伍 ID、原始队名与规范化队名的对应和出现次数。
- `m2/train.csv`、`m2/val.csv`：新版历史特征，兼容 `design()` 的 41 列输入约定。
- `manifest.json`：数据指纹、处理计数及与 v2 的特征比较。

`manifest.json` 中特征差异使用 `rtol=1e-10, atol=1e-12` 比较，其中也可能包含稀疏求解器重算产生的微小数值差异。它不是“改善了多少场比赛”，更不是模型性能提升。

正式 `train_m1_m2.partition()` 仍固定读取 clean_v2。要研究本候选版，应另外建立实验入口和产物目录，不能用新版 CSV 替换被冻结的数据。

## 复现与核验

在仓库根目录运行：

```powershell
F:\venvs\ml-cs2\Scripts\python.exe -B -m scripts.build_clean_v3
F:\venvs\ml-cs2\Scripts\python.exe -B -m scripts.build_clean_v3 --verify
F:\venvs\ml-cs2\Scripts\python.exe -B -m unittest discover -s tests
F:\venvs\ml-cs2\Scripts\python.exe -B -m scripts.train_m1_m2 verify
```

只生成清洗表、不重建历史特征时可使用 `--tables-only`。构建器会写入固定的 clean_v3 目录；反复生成时按 manifest 中的文件清单使用产物。

新增 14 项边界测试覆盖统计矛盾、ID 合法性、阵容重复与交叉、重复记录补全、冲突隔离、原始行保留，以及不根据异常值随意改比分等情形。连同原有测试共 41 项通过。

## 仍不能凭现有文件解决的问题

缺失的地图、没有独立赛前来源的赛制、赛事别名、同名组织身份和异常统计真值，都需要新的可靠来源。清洗后不能保证准确率提高；本版首先提高规则的可检查性和数据的可追溯性。后续选参仍只能使用训练/验证数据，已经使用过的测试集不能重新充当独立的新测试集。
