# v9 原始快照 · 第二版清洗（clean_v2）

原始来源和冻结的 v9 没有覆盖。两版逐行比较的 11,387 个 `match_id`、UTC 时间、队伍方向、胜负标签、分区均相同。训练 7,260、验证 1,968、最终测试 2,159。完整比赛表和地图表已重建；仅对训练和验证生成赛前特征，没有运行预测或评估最终测试集。

**地图。** 只保留有有效比赛主记录、能确认胜负和两队方向的地图。地图名去空格并统一大小写，同场同名地图不得重复计数。同一地图有两条互相矛盾的回合比分时，两条原始候选都隔离，不任选其一。旧地图表的 12,399 行变为 12,387 行：11 行没有保留下来的比赛主记录，另 1 行是旧逻辑曾从冲突的两条候选中任选的记录。`maps_complete` 表示已确认完整：已识别的赛制和系列赛比分相容，记录地图的双方胜场分别等于终场比分，且没有待核的冲突地图。False 包括缺失和无法确认；`map_score_verified` 可单独检查逐图是否还原比分。BO3 的 2:0、2:1 与 BO5 的 3:0 都可完整。例如 Monte 对 Passion UA（7298868）已由 False 改为 True。

**赛制。** `bo_reported` 保留原始值。`bo_score_conflict` 是赛后质检标记，不说明真实赛制或胜者一定错误。现有输入未附可独立核验的赛前赛制来源，因此本版供训练的 `bo` **全量置为未知**，包括比分相容的记录；`bo1/bo3/bo5` 均为 0，`bo_missing` 为 1。这避免了用赛果决定「这一场的赛制是否可用」而间接泄漏结果，代价是暂时停用赛制的预测信号。后续如有赛前公告，可按比赛 ID、公告时间和来源覆盖，不应由当场比分回填。

**阵容。** 同队 ID 重复，隔离该队整份阵容；跨队重合，隔离双方。逐图的选手统计另查本图 ID，仍屏蔽比赛级已隔离的一方。能确认的另一队、比赛胜负和独立可靠的地图不受牵连。本场的缺失阵容不会用于刷新之后比赛的最近完整五人名单。双方赛前均无队史时依然是信息缺口，清洗不能补造队史。

**交付与使用。** [比赛主表](matches.csv)、[地图表](maps.csv)、[逐场质量记录](match_quality.csv)、[冲突地图候选](rejected_map_rows.csv)、[数据校验清单](manifest.json)。正式 M1/M2 均使用[训练特征](m2/train.csv)和[验证特征](m2/val.csv)。M1 读取 31 个基础输入；M2 使用 `scripts.train_m1_m2.design` 生成 41 列。质检字段和当前比分不得作为本场输入。

在项目根目录运行 `python -B -m scripts.build_clean_match_dataset` 可从固定 v9 复建清洗产物；CSV 指纹忽略 CRLF/LF 差异。正式训练、复核及 M3 数据接口见[队员交接说明](../../../docs/TRAINING_PROTOCOL.md)。
