# M3：M2 与 LightGBM 的独立堆叠实验

**结论：暂不替换 M2。** 以 clean_v2 的现有胜率模型为底层，两个学习权重的融合都没有在训练期的向前检验中超过「仅调整 M2 概率」的对照。开发验证里，学习加权平均对原 M2 的 log loss 改进只有 0.000082，按比赛日配对重采样的 95% 区间跨零。这是 M3 的第一轮融合实验，不包括 MLP 或 LSTM。

| 方案 | 训练期向前检验（4,998 场）准确率 / log loss | 开发验证（1,968 场）准确率 / log loss |
|---|---:|---:|
| 原 M2（训练期一列仅作回顾性参照） | 61.38% / 0.653290 | 63.26% / 0.633779 |
| 向前选参的 M2 | 61.38% / 0.654262 | 63.26% / 0.633779 |
| LightGBM 单独 | 60.56% / 0.658119 | 63.67% / 0.636491 |
| 仅对 M2 做概率缩放 | 61.38% / **0.654004** | 63.26% / 0.634015 |
| 两模型概率 50:50 平均 | 61.22% / 0.654699 | **63.97%** / 0.634095 |
| 学习两模型的概率平均权重 | 61.40% / 0.654477 | 63.31% / **0.633697** |
| 非负权重 logit 堆叠 | 61.36% / 0.654214 | 63.26% / 0.633936 |

## 如何判断

- 向前检验中，以同样向前选参的 M2 为起点。仅调整其概率，log loss 从 0.654262 降至 0.654004；加 LightGBM 后，两种学习融合损失反而分别增加 +0.000473 和 +0.000210。logit 堆叠在最后三折都将 LightGBM 权重设为零，与仅缩放 M2 一致；第一折加权后表现更差。两种融合都没达到预设门槛：合并 log loss 更低，且分别在至少 3/4 折胜过向前 M2 和缩放 M2。
- 开发验证用训练期全部 6,185 场底模留出预测拟合权重。概率平均学到约 **94.18% M2 / 5.82% LightGBM**，较原 M2 净多猜对一场，损失差 −0.000082，95% 区间 [−0.000343, +0.000172]。50:50 平均净多猜对 14 场，但 log loss 变差，训练期的准确率和 log loss 也未优于向前 M2。以概率质量为目标，不据此换主模型。

## 时间隔离与复现

底模是现有 M2 与使用同一 41 列的浅层 LightGBM。复算原五个训练期时间折的固定参数组合，每场底模输入都是由更早的比赛拟合后生成。第二层用第一折作为起步数据；在第 2–5 折中，底模参数选择和融合权重拟合只使用更早的留出记录，并在评分折前留 30 天。底模每折拟合也保留其原有的 30 天隔离。原 M2 在训练期的数值因其参数是用全部五折后选的，只作回顾参照，不参与向前晋级门槛。

概率平均的权重被限制在 [0,1] 且和为 1；logit 堆叠没有截距，给两模型对数几率拟合非负系数；单模型缩放对照只调整 M2 对数几率的幅度。对交换双方，这些方法都保持概率互补。所有参数在开发验证前锁定；锁定的底模逐场结果与既有预测核对一致。开发验证仅作诊断，早已被多轮使用；最终测试集没有打开评分，现有 M2 文件未改动。

复现：在项目根目录运行 `.\.venv\m1\python.exe -B -m scripts.experiment_m3_stacking select`，再以 `validate` 替换 `select`。
