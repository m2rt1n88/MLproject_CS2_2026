# M3 最终测试：孪生 LSTM 与 M2 + LSTM 融合

**结论：融合的测试 log loss 比 M2 低 0.00127，95% 区间 [−0.00319, +0.00066] 跨零；准确率反而少对 6 场。孪生 LSTM 单独与 M2 的 log loss 相同，少对 16 场。** 两者都不能说比 M2 更好，主模型仍是 M2。

测试期 2026-04-01 至 2026-10-31，共 2,159 场。融合配方是训练期向前筛选选中、并在评测前提交的 `m2+lstm/mean`（两模型概率各占 0.5）。

## 全场成绩

| 模型 | 准确率（正确场数） | log loss | Brier | ECE | 与 M2 的 log loss 差，95% CI |
|---|---:|---:|---:|---:|---|
| M2（冻结） | 62.76%（1,355） | 0.63324 | 0.22165 | 0.0185 | — |
| 孪生 LSTM | 62.02%（1,339） | 0.63324 | 0.22176 | 0.0176 | +0.00000 [−0.00386, +0.00387] |
| **M2 + LSTM 融合** | 62.48%（1,349） | **0.63197** | **0.22109** | **0.0175** | −0.00127 [−0.00319, +0.00066] |

置信区间来自配对 bootstrap，以比赛日为单位整天重采样，2,000 次，种子 2026。

## 怎么读

- 融合在三个赛事等级的 log loss 都略低于 M2，方向和开发验证一致（开发验证差 −0.00140）。但单次测试的差距仍在噪声范围内，不能当作确定的改进。
- 准确率和 log loss 方向不同：融合少对 6 场，但 log loss、Brier 和 ECE 都更低。准确率只看是否过 0.5，差几场属于正常波动；本项目以 log loss 为主指标。
- 70% 的全场准确率目标没有达到。阈值 0.60 时三种模型都在约 51% 的比赛上超过 71%，这是选择性预测成绩，需要和全场成绩分开报告。
- 测试集此前已用于评估 M2（见 [M4.md](../M4.md)），所以 M2 的测试成绩在本次评测前已经公开。LSTM 与融合的选择全部在训练期和开发验证上完成，配方在打分前提交（提交 `e22303c`、`2e6e946`），测试成绩没有回流到任何选择。

## 防泄漏检查

- 测试期特征按 `build_test_features` 的方式用全部比赛在线重建；train/val 部分与发布版 85 列逐列一致。
- 重算的 M2 测试概率与 `reports/release/m2_test.csv` 最大相差 1.76e-07，融合使用发布版概率。
- LSTM 在测试期按天更新历史：当天比赛先全部打分，当天结束后才写入赛果。抽查 6 个测试日，截断到当天并翻转当天全部赛果后，LSTM 预测最大变化为 0。
- `predict` 阶段不计算任何指标；`evaluate` 先核对锁定配方、LSTM 权重和两份预测文件的哈希，再算指标，并拒绝第二次运行。

## 复现

```powershell
python -B -m scripts.score_m3_test predict    # 重建特征、打分、泄漏抽查
python -B -m scripts.score_m3_test evaluate   # 只能运行一次，重评需 --force
```

需要 `requirements-m3.txt` 的环境和本地 LSTM 权重 `models/m3_lstm/lstm.pt`（不进仓库，可由 `python -B -m scripts.train_siamese_lstm train` 重建）。机器可读结果见 [test_metrics.json](test_metrics.json) 与 [test_manifest.json](test_manifest.json)。
